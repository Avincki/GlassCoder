Scope

This is an opinionated product ranking, not a benchmark leaderboard. Scores assume GlassCoder’s MCP layer works as designed: Learn + GitHub tools behind admission policy, budgets, and record/replay. Default install still has retrieval off (Retrieval:Enabled: false).

GlassCoder is not priced or designed as “a cheaper Cursor.” Its job is a measurable, sovereign .NET harness — capability ≈ model × harness × context.

04

What MCP changes

Before MCP

  • Local models invent APIs and packages; the ladder often catches only after wasted steps.
  • Frontier agents effectively “know” more public surface and can search freely.
  • GlassCoder context was almost entirely workspace tools, not authoritative external surface.

With working MCP

GainedHow
Authoritative .NET / Azure surface Learn when compile names non-workspace symbols
Hallucination check GitHub code search as existence, marked untrusted
Still scientific Record/Replay corpus; miss is loud; tools absent when off
Still budgeted Max calls, max result chars, anti-search loop
Not gainedWhy
Match Claude/Cursor on open-ended product coding Model + general tool breadth + polish
Fix UI layout / “visible in dialog” Needs Run app / layout harness, not docs
Free browsing like a general agent AllowProactive=false by default; tight budgets

Net: MCP moves GlassCoder from “local .NET harness with blind spots on external APIs” toward “local .NET harness with controlled, measurable external knowledge.” Meaningful upgrade versus other local agents on .NET; only a partial catch-up to frontier on knowledge — not on general agency.

05

Head-to-head

Vs other local agents

GlassCoder usually wins on .NET verification depth, Lab/metrics, safety defaults, and external Microsoft docs without wrecking science. Local peers usually win on polyglot speed, ecosystem size, and install-and-go lightness.

With MCP, GlassCoder is among the more serious local options for .NET shops that care about sovereignty and measurement — not the best generic local Copilot clone.

Vs frontier cloud agents

Frontier wins raw task success, speed of greenfield “anything,” and broad web knowledge. GlassCoder wins privacy/air-gap, bill control on own GPUs, auditability of agent behaviour, and comparing harness configurations.

With MCP, the gap on Microsoft-ecosystem factuality shrinks; the gap on open-ended software engineering barely moves. GlassCoder remains a complement or alternative for constrained environments, not a drop-in Claude Code replacement.

Hybrid: frontier model + GlassCoder harness

# Often the strongest combo for serious .NET shops
hosted Opus/GPT as worker
  + GlassCoder tools / ladder / MCP Replay
  + optional local or remote critic

Frontier model quality, GlassCoder oracles and measurement, optional Learn with a recorded corpus so Lab arms stay fair.

07

Residual weaknesses

  1. Model-bound. Qwen FP4 on Spark is not Opus on hard multi-file design.
  2. UI / runtime evidence. Critics can still refute without Run app; MCP will not fix that.
  3. Python and other languages remain second-class without tool packs.
  4. MCP effectiveness on the suite is still unproven until external-doc fixtures exist.
  5. Proactive Live MCP without budgets reintroduces thrash.
  6. Product polish and ecosystem remain far behind Cursor / Claude Code.

One sentence summary before the rankings: with MCP working, GlassCoder is a state-of-the-art local/.NET agent harness with measurable, hermetic external knowledge — still behind frontier models on open-ended coding, and ahead of most local agents on verification, governance, and experiment design.
