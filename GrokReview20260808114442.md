### Task E3 — Post-completion-critique recovery gate (P0, high ROI)

**Problem:** After 2/3 refute, agent spent steps 20–28 on packages + build + unit tests, marked “integration tests” complete without writing any, then Completed. Critique is single-shot (`critiqueSpent`).

**Do (minimal effective design):**

1. After a **refuting** completion critique, do **not** accept the next no-tool completion unless:  
   - at least one **Applied** code change landed since the refute, **or**  
   - a second critique is run and does not refute, **or**  
   - (optional config) max post-critique steps exhausted → stop with caveat rather than silent Complete.  
2. Inject **one** short user message after refute, e.g.:  
   - *Critics need stronger evidence. For UI goals, unit tests of a service alone are not enough; operator Run app validates the window. Adding packages without new tests does not address the refute.*  
3. Do **not** implement full FlaUI automation in the agent loop in this task.

**Files:**  
- `src/GlassCoder.Core/Agent/AgentLoop.cs` (completion + critique boundary)  
- Critic / agent loop tests  

**Acceptance:**

- [ ] Simulated: refute → no-tool claim with no new applied changes → not Completed.  
- [ ] Simulated: refute → create_file/edit applied → no-tool claim → can Complete (or second critique runs).  
- [ ] Token impact of second critique documented if always enabled.

**Efficiency:** Would have cut roughly **8–10 steps and tens of k tokens** on `f4ed50e0`.
